## Context

参考页面的相关区域是“值多少钱：按占全球可配置资产比例分档”，并有周期目标与资金流交叉检查。该页没有给出足够可核验的资产池总额来源，因此本模块将资产池作为明确的可编辑情景输入，不包装成实时宏观统计。原站的资金乘数同样属于情景变量。

## Goals / Non-Goals

**Goals:** 展示目标、资产占比和资金需求之间的数学关系；用户调参数即可看到资金压力的变化；复用现价并继承已有过期规则。

**Non-Goals:** 给出交易指令、预测目标必然实现、复制参考站整段投资分析、增加上游数据接口或后端、把参考站数字当成已验证事实。

## Decisions

- 新区 `#targets` 放在周期/成本锚之后、风险之前。导航增加“目标”，样式沿用现有卡片、留白和响应式规则。
- 一个独立 `assets/cycle-targets.mjs` 同时提供纯计算函数和窄 UI 接口；模块导入不自行访问 DOM 或发请求。`dashboard.mjs` 初始化它，并在价格更新及 `refreshDerived()` 时传入有效现价。模块本身不新建计时器。
- 配置 API：`{assetPoolT:300, supplyM:20, targetPrice:170000, impactLow:15, impactHigh:20, yearsLow:2, yearsHigh:3}`。金额内部一律 USD，供给一律 BTC；T/M 只出现在输入与格式化边界。所有默认值明确标为假设或参考情景。
- 提供“参考参数”重置和“保守 5×”压力情景；后者只改资金放大倍数，不重置用户其他输入。不新增持久化设置或外部写入。
- 输出当前市值与占比、目标情景的目标市值/占比、市值增量、累计资金需求区间、年均/月均区间；再列 1%、1.5%、2%、2.5%、3%、5% 配置档位的同口径测算。情景条件用简短自写描述，不宣称条件已发生。

### Formulas

令 G=资产池USD、N=供给BTC、P0=有效现价、Pt=目标价、q=配置占比、kL/kH=市值放大倍数、YL/YH=年限：

```text
当前市值 C0 = N × P0
配置档位目标市值 Cq = G × q
配置档位目标价 Pq = Cq / N
手动目标市值 Ct = N × Pt
目标占比 = Ct / G
正向市值增量 ΔC = max(Ctarget − C0, 0)
累计资金需求 = [ΔC / kH, ΔC / kL]
年均资金需求 = [ΔC / (kH × YH), ΔC / (kL × YL)]
月均资金需求 = 年均 / 12
```

现价 $80,000、供给20M、资产池$300T、目标$170,000、乘数15–20、期限2–3年时：C0=$1.6T，Ct=$3.4T，ΔC=$1.8T；累计=$90–120B，年均=$30–60B，月均=$2.5–5B。参考页“年均40–60B”不是上述完整区间的数学下界，本实现不照抄。

### Validity and isolation

参数必须有限、正数，供给不超过21M BTC，区间下界不大于上界。派生计算溢出也视为无效。无效输入就地显示中文错误，并清除该模块受影响结果，不能显示 NaN/Infinity 或让其他指标请求失败。

现价缺失或超过现有5分钟门槛时，目标价/市值仍可独立计算，市值增量和资金需求显示不可计算；不能假设P0=0。目标低于现价时，正向资金需求为0并标“已达到该情景”，不伪造负需求。模块 DOM 缺失时提供 no-op 句柄，避免旧 HTML/新模块短暂混用影响主看板。

## Risks / Trade-offs

- [乘数不是稳定因果参数] → 明示为情景估算并提供5×压力值；不把所需净流入当预测。
- [资产池口径不唯一] → 默认$300T明确为假设，用户可调；不引入未经核验的财富统计。
- [流通供给会变化] → 20M作为可编辑供给假设，不宣称为实时供应量。
- [资金流尺与占比尺并非独立证据] → 两者均由同一目标市值推导，在模块说明中明确。
- [新增模块影响首屏] → 小型无依赖模块、modulepreload、无新增网络数据请求；输入渲染按帧合并，原页面测试继续通过。
