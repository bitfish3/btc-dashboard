## Why

看板的静态页面很轻，但数据请求、缓存、调度和 DOM 渲染集中在一个 inline script 中。现有交接记录、线上初轮 QA 与代码核对显示：慢响应体不受超时约束、部分链上指标只加载一次、故障缺少明确状态，并且派生指标可能使用无效或固定值。这些问题直接影响响应速度和数据可信度。

## What Changes

- 在现有 Cloudflare Pages 静态部署内拆出请求/缓存/调度运行时、数据源适配器和页面控制器；保持无构建和无生产依赖。
- 请求从连接到 JSON 解码全程受超时约束，价格与历史 K 线多源竞速并取消落败请求，每个数据任务不重叠执行。
- 内存与 localStorage 双层缓存只接受经过校验的值，恢复全部支持的卡片，区分获取时间、数据来源时间、过期和不可用状态。
- 按指标频率刷新；后台标签页暂停定时请求，恢复前台时仅刷新到期任务；有效价格到达后重算派生指标。
- 独立加载 STRC 两个来源，失败不抹掉另一来源的可用结果；移除虚构 PSIP 与 MSTR 默认币价，证据不足时不显示确定的周期结论。
- 保留每周脚本依赖的 `index.html` 两个常量标记；补充确定性回归测试、真实浏览器验证和交接说明。

## Capabilities

### New Capabilities

- `dashboard-runtime`: 有界请求、有效缓存、单任务调度与可观察的数据状态。
- `dashboard-data-integrity`: 数据源校验、独立降级、派生指标依赖与证据覆盖率。
- `dashboard-delivery`: 保持静态部署兼容、周更常量契约与可重复验证。

### Modified Capabilities

无既有 OpenSpec specs。

## Impact

影响 `index.html`、新增 `assets/*.mjs`、本地测试及文档。沿用现有 Pages、Worker 和公开 API，不增加基础设施、不迁移 KV、不更改远端服务。原项目两个未提交 Worker 文件已备份并留在原目录，本分支不吸收、不回退这批工作；Worker 部署版本漂移作为已知运维限制记录。发布/push 在本地实现及验证完成后单独确认。
